# Define Job-Seeking Loop Use Cases

This Episode records framing LevelMatch's next direction as a two-sided job-seeking
loop and capturing five candidate-side use cases as proposed Goals.

## Context

With the MVP deployed, the steward articulated a vision: LevelMatch should close the
full job-seeking loop and match candidates to roles to the benefit of both
candidates and hiring managers. Five sequenced use cases form the candidate arc.

## Participants

- project steward
- Claude (claude-opus-4-8)

## Inputs

- The deployed MVP (ingest → extract → gap analysis)
- The steward's two-sided loop vision
- Process: start each use case as a proposed Goal (a proposed will-apt commitment),
  validate via Claims, fork via Alternatives, bound via Constraints, then accept

## Outputs

- Active vision Goal: `two-sided-matching-loop`
- Proposed Goals: `resume-upload-matching`, `resume-upgrade-suggestions`,
  `prep-plan-generation`, `prep-plan-followthrough`, `auto-apply`
- Each proposed Goal carries the Claims to validate and the main fork inline, to be
  promoted to real Claim/Alternative primitives when its development begins
